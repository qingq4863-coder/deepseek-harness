# Agent Note：安装与卸载在一条显式审批决定之后运行固定的管理器命令

Status: implemented

[English](2026-09-09-pkg-mutation.md) | 中文

## Problem

安装器规划的 §4.4 流程走到后半段：候选查询回答了「安装它会发生什么」而不改变任何东西，剩下的问题是模型究竟如何真正安装或移除一个包。§7 要求对这一段扩张的两类面给出显式授权——网络可达面，因为管理器会从其配置的来源取回或移除产物；以及机器变更面，因为安装器会改变机器。授权之后，工具的形状由它必须**不能**做到的事决定：不能接受模型给出的命令、参数或版本；在决定为拒绝时完全不能运行；也不能把管理器的退出码当作机器已改变的证明。

## Decision

`pkg_install` 与 `pkg_uninstall` 各自运行一条固定的包管理器自有 argv。安装为 `winget install --id <name> --exact --silent --accept-package-agreements --accept-source-agreements`、`npm install -g <name>` 或 `pip install <name>`；卸载为 `winget uninstall --id <name> --exact --silent`、`npm uninstall -g <name>` 或 `pip uninstall -y <name>`。模型只提供管理器与包名，别的都不提供；包名通过 `pkg_propose` 使用的同一套校验——必须以字母数字开头，且只含字母、数字、点、下划线、加号或连字符——因此它作为单个 argv 元素传递，既不会变成标志也到不了 shell。

两个工具都声明 `capability.approval: 'explicit'`，因此工具注册表在派发**之前**索要决定：非允许的结果会拒绝调用、把拒绝作为工具错误返回，且永远到不了调用体。这是唯一的门禁。调用体不重复请求，因此工具不会问第二次，被执行的正是所声明的能力承诺的那一个决定。能力声明写清这次调用的代价：`dataClass: 'sensitive'`、`risk: 'high'`、`reversible: true`，`writeScope` 指明经所选管理器改动机器上已安装的软件包，`network` 指明管理器自身从其配置来源取回或移除。没有归属 agent 会话的调用会失败，因为该决定无处记录。

结果是 `ok`、`unavailable`、`denied` 或 `failed` 之一，进程运行并退出时附带管理器的退出码，失败说明中附带经清洗的管理器 stderr 尾部。`pkgInstallTimeoutMs` 约束一次运行并中止其进程树；每条流都有上限。成功渲染为管理器报告的内容，并点明调用方欠下的确认：调用前捕获的 `apps_snapshot`，调用后与 `apps_diff` 比较。两个工具都不声称已验证的机器变更，也都不保留变更日志。

## Alternatives considered

**像 `env_version` 那样在调用体内经 `ctx.approval.request` 询问。** 拒绝：注册表的显式门禁已经覆盖整个调用，再请求一次会让同一个决定提示两遍，也会让调用体的门禁与所声明的能力发生偏移。只设一个门禁，并且声明在注册表能看到的位置。

**在工具内部重新探测管理器清向来验证变更。** 拒绝：`pkg_inspect` 探测的是一个管理器自己的记录，而一次变更可能增加、移除或升级另一个管理器持有的东西，且管理器对某个包的自身记录并不等于机器上的应用状态。验证留在本包已经放好的位置——调用前 `apps_snapshot`、调用后 `apps_diff`。

**让模型传入版本或额外标志。** 拒绝：模型提供的标志恰恰是值得收回的那种变更面，而锁定版本本就是管理器策略与 `pkg_propose` 已经回答的决定。

**让本包保持只有候选查询。** 拒绝：用户已显式授权安装与变更那一半，而这正是 §7 设定的条件。

## Consequences

模型只能按名字安装或移除软件包，被拒绝的调用不产生任何进程。报告的成功就是报告：本包对机器变更的唯一证据仍是快照／差异那一对，这也是两个变更工具成为本包仅有的 `risk: 'high'` 条目的原因。测试固定了每个管理器与动作的固定 argv、无进程产生的拒绝路径、可执行文件解析不到时报告 `unavailable` 且不产生进程、携带经清洗 stderr 尾部的非零退出、超时、非法名与未知管理器的失败，以及运行被信号终止时退出码缺失。回滚与对已取回产物的来源验证仍未实现；`pkg_uninstall` 是管理器的逆操作，不是回滚到某个捕获过的版本。
