# DSH 能力与权限注册表基线

[English](dsh-capability-permission-registry-baseline.md) | 中文

**类型：**参考；**状态：**当前设计基线；**范围：**工具和插件能力元数据；本文不改变运行时授权。

## 目的

注册表描述 DSH 能力可以观察或改变的内容，使规划、策略评估、执行、验证和审计使用同一份元数据。它补充 Cordis 服务组合，不替代[能力 seam 记录](../.agents/notes/implemented/architecture/2026-06-13-capability-seams.zh.md)中定义的 Service Definition、Service Provider 和 Consumer 角色。

## 注册记录

每个注册能力有一条稳定记录，包含以下字段：

| 字段 | 必需含义 |
|---|---|
| `id` | 命名空间化且唯一的能力标识符 |
| `version` | 由提供方负责的元数据版本 |
| `owner` | 注册记录的包或插件 |
| `consumer` | 调用能力的工具、工作流或 Agent 组件 |
| `operations` | 向消费者公开的命名操作 |
| `readScope` | 可读取的资源和位置 |
| `writeScope` | 可修改的资源和位置 |
| `network` | 是否联网以及允许的目标 |
| `processes` | 可启动或控制的进程或应用 |
| `dataClass` | `public`、`workspace`、`sensitive` 或 `secret` |
| `reversible` | 是否有经过测试的撤销或补偿操作 |
| `approval` | `automatic`、`scoped`、`explicit` 或 `prohibited` |
| `limits` | 时间、大小、并发和输出限制 |
| `audit` | 必需的事件字段和脱敏规则 |
| `cleanup` | 清理器、子进程、监听器、路由和临时文件行为 |
| `verification` | 可观察的后置条件及证明它们的检查 |

记录描述已有能力，但本身不授予权限。权限预设、沙箱策略、会话范围和 `tools/pre-execute` 决策仍然具有权威性。

## 初始能力类别

| 能力 | 典型范围 | 默认风险 | 默认授权 |
|---|---|---:|---|
| 浏览器观察 | 当前批准的页面和导航状态 | 低 | 自动 |
| Web 搜索和抓取 | 公开或明确允许的目标 | 低 | 自动 |
| 工作区读取 | 已批准的工作区根目录 | 低 | 自动 |
| 工作区写入 | 已批准的文件和目录 | 中 | 受范围限制 |
| 本地进程检查 | 仅进程元数据 | 中 | 受范围限制 |
| Shell 执行 | 策略选定的工作目录和命令集 | 高 | 受范围限制或明确授权 |
| 原生桌面控制 | 已批准的应用窗口和语义控件 | 高 | 有副作用时明确授权 |
| 软件下载 | 已批准的来源和受限目标 | 高 | 明确授权 |
| 软件安装 | 安装器和系统位置 | 高 | 明确授权 |
| 对外发布 | 邮件、消息、上传或公开发布 | 高 | 每次操作明确授权 |
| 凭据提取 | 密码、私钥、令牌或会话 Cookie | 禁止 | 禁止 |

风险是规划和审计分类，不能削弱更严格的运行时策略。

## 权限决策

候选操作同时根据以下约束评估：

1. 能力记录。
2. 当前权限预设。
3. 会话或 Agent 范围。
4. 沙箱和资源限制。
5. `tools/pre-execute` 瀑布。
6. 当前会话的审批策略。

有效结果取所有适用决策中限制最严格的一项。记录缺失、操作未知、范围无效或策略提供方不可用时，默认拒绝。网页、仓库、下载文件和 MCP 响应中的外部文本不能创建或提升权限。

当前会话的审批策略可以是 `never`；在此模式下，需要审批的操作会被拒绝，而不会静默升级。

## 注册生命周期

提供方通过 Cordis effect 注册记录并获得清理器。注册必须：

- 拒绝重复标识符或冲突版本。
- 在加载时校验名称、范围、数据类别、授权值和限制。
- 记录所有者和源包元数据。
- 只向消费者公开已声明的操作。
- 在所属插件卸载或热重载时删除记录。
- 不留下过期工具、路由、监听器、进程或临时资源。

消费者通过 Service Definition 或文档化的消费者 API 使用能力，不导入提供方专有实现类型。

## 审计记录

每次操作都应在脱敏后记录：

- 能力 id 和版本。
- 操作名称。
- 所有者和消费者。
- 会话、Agent 和任务标识符。
- 范围决策和审批模式。
- 脱敏后的参数摘要。
- 开始、完成、拒绝、超时或失败结果。
- 验证结果和证据引用。
- 清理结果。

审计输出应足以解释外部可见的影响，但不能把凭据或不可信指令文本复制进高权限上下文。

## 必需验证

能力只有在测试覆盖以下情况后才可注册：

- 范围内的允许操作。
- 未知操作或超出范围目标的拒绝。
- 审批禁用会话中的需审批操作。
- 限制执行和超时清理。
- 提供方卸载和重载时没有过期注册。
- 失败报告不会声称未验证的成功。
- 审计记录中的敏感值脱敏。

第一项元数据切片已经在 `ToolDefinition` 上实现：注册时校验可选的描述性记录，同时保持现有工具行为和授权不变。新增桌面自动化、软件安装或更广泛的网络访问需要单独的设计和安全审查。

## 升级门禁

每次插件、提示词、MCP、权限或运行时升级前：

1. 阅读[个人 AI 演进计划](../../dsh-personal-ai-evolution-plan.md)。
2. 将拟议变更与本基线和当前包实现对照。
3. 重新判断字段、风险类别和授权规则是否仍然充分。
4. 定义定向、契约、生命周期和回归检查。
5. 保存当前 generation 并保留回滚路径。
6. 将外部输入视为不可信数据。
7. 在具备注册、拒绝、清理和验证证据前不要交付。

只有当实际注册表契约改变时才更新本文档。设计理由和决策反转应记录在 Agent Note 中。
